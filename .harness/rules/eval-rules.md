# 评测规则

评测代码放在根目录 `eval/`：dataset 构建与冻结题集，retrieval 跑实验、评分和指标；独立于入库和检索策略。

核心约定(用户定,2026-10-03):
- 评测题只和原始 PDF 关联,不绑定 chunk、解析结果或检索配置。每题保存问题、参考答案、doc_id、页码、证据原文。
- 证据以原始 PDF 为准。解析文本可以辅助出题,人工审核必须核对 PDF;换解析方式不改变评测依据。
- 文档同时保存文件哈希,固定语料版本;文件变了,相关题标为待复核。
- 每次评测判断检索结果是否覆盖这些原始证据,解析遗漏、切分不完整、检索没找到都在同一套题上体现。
- 参考答案不要求逐字匹配:检查关键事实是否正确、是否有证据支持。
- 先做 50 题。

保留的约定:同客户/使用方构建标准测试题。只比较相同语料、相同标注集上的配置,v1 和 v2 不混比。评测使用同一套标注和评分规则,记录配置和代码版本,先看 Recall@k、MRR。

实现(2026-10-03,2026-10-04 按审核意见修订):
- 语料快照 `EVAL.SNAPSHOT_CORPUS`:每个 PDF 记 sha256,用 pypdf 6.8.0 抽每页文字层存 `EVAL.PDF_PAGES`。快照名一次性,语料变了用新名字。换抽取工具不能复用已有文字层。
- 文字层只用来辅助出题和定位证据,会抽错字符(− 变成 /C0、= 变成 ¼)。最终依据是审核时在 PDF 上核对过的证据;按 PDF 改过的证据可能在文字层里定位不到。
- 定位用 `EVAL.NORMALIZE_TEXT` v2(小写,只留 a-z、0-9)和 `EVAL.EVIDENCE_LOCATED`。它去掉所有符号(−6.1 和 6.1 一样),只用于定位,不能单独作为答案正确或检索覆盖的评分依据;评分规则随评测过程另定,改了要记在这里并重算历史结果。
- 表格题的证据要能单独看懂:`evidence_parts` 存表名、列标题、行标签和数值等多个原文片段,评分时要求一起覆盖,不能只命中数字。
- 草稿 `EVAL.DRAFT_QUESTIONS`:按种子抽文档、五种题型轮流,AI_COMPLETE 读文字层出题,状态 DRAFT,记模型、prompt 版本、种子和批次。只给还没有题的文档出题;页码自动纠正只改本批。AI 起草、审核通过的题 source 仍是 AI_DRAFT,不称为客户或专家标注集。
- 审核导入 `EVAL.APPLY_REVIEW`:决定写进 `EVAL.REVIEW_IMPORT` 后应用。APPROVED 直接通过;REVISE 写成新题(revised_from 指向原题,状态 DRAFT,要再复核),原题设 REJECTED。只有 APPROVED 参与评测。
- 题集 `EVAL.FREEZE_QUESTION_SET` 固定后不再变,加题换题用新题集名;实验只在同一题集上比较。`qset_v1` = 快照 corpus_2026_10_03 的50道库状态 APPROVED 题（2026-10-04）；本轮发现其中两题证据表名未修正，修订成新题并复核后另建题集，不直接覆盖冻结题目。
- 检索评测 `EVAL.RUN_RETRIEVAL_EVAL`:逐题调检索服务存 top-k 原始结果,`EVAL.RESCORE_EXPERIMENT` 判定,`EVAL.RETRIEVAL_METRICS` 出指标(文档级和证据级 hit@1/5/k、MRR,上限 coverable_rate,延迟)。新影响因素放 EXPERIMENTS.params,不加列。
- 评分规则 `EVAL.EVIDENCE_COVERED`,当前 v2:每个证据片段的词至少 90% 出现、数字(带小数点和负号)全部出现,所有片段要在同一个块里。v2 只修了格式处理(字母间连字符、`--` 不算负号、千分位)。改规则要记在这里,并对历史实验 RESCORE。
- 上限 coverable：该配置、快照 etag 的现有块中是否有一个块满足全部证据片段的覆盖规则。FALSE 只表示当前单块规则未通过，也可能由评分误差、版本块缺失引起；需逐题核对后才能归因到解析/切分。它不衡量 top-k 多个块合起来是否足够回答。
- 当前 v2 是词袋启发式，不能确认词与数值的对应关系或比较符号：本地复现中组别/数值对调及 ≥/≤ 相反均返回 TRUE。评分校准前，指标作为初步观察。
- 指标分母应来自固定题集，零结果题计未命中，未完成实验不作为最终结果。本地新版从完成实验的冻结题集起算，云端尚未部署；历史基线50题都有返回，未触发零结果漏计。
- 目前检索结果未保存 etag，重算上限会读取实时 CHUNKS；比较前核对服务、配置和文件版本一致，保留实验时的覆盖依据，不能将实时块变动混入历史策略比较。

实验结果只写在 `docs/experiments/`(索引是 README.md),这里只记规则。

实验约定(2026-10-04):
- 一个 config_name 可以对应多个搜索服务；检索层的变化(标题前缀、multi-index、权重)记在 EXPERIMENTS.params,不另建切分配置。
- 服务返回原始 chunk_text 用于评分；为检索注入的标题(search_text)不算证据，单块上限仍读取原配置的 CHUNKS。
- 权重通过 RUN_RETRIEVAL_EVAL 的第 7 个参数 scoring_config 按请求传入，不改服务默认、不重建服务或 embedding。
- `qset_v1` 已用于比较和调参，在它上面的最好成绩是探索结果；验证泛化要用独立的新题集。
- 表格题 8 题里有 2 题没有 evidence_parts，证据实际在正文，不能只用表格块衡量。
- 实验 ID 只用一次，重跑换新 ID，不覆盖历史实验。
