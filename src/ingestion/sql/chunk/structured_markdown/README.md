# 结构化 Markdown 切分

structured_markdown 表示按 Markdown 的标题和表格结构切分。这个策略要解决两个问题：按页切会截断跨页段落；通用字符切分会把表名、列标题与数据行分开，使数值失去含义。它先把论文拼成一份 Markdown，再分别处理正文和表格。当前只生成一层可检索块。

```text
解析页 → 规范化全文与页码坐标 → TEXT / TABLE 元素
       → 正文按标题切 / 表格按行组切 → 标注章节与页码
       → 精确 token 检查与少量补切 → CHUNKS
```

## 各步骤做什么

| 文件 | 输入 → 输出 | 为什么单独处理 |
|---|---|---|
| `prepare_document.sql` | pages → 全文、每页字符范围 | 跨页切分与页码定位共用同一个坐标系 |
| `extract_elements.sql` | 全文 → TEXT/TABLE、表头、行组、原文位置 | 防止通用 splitter 破坏表格结构 |
| `build_table_chunks.sql` | 表格及逐行 token → 重复上下文的表格候选 | 在窗口内尽量保留行组及数值归属 |
| `annotate_chunks.sql` | 全文、候选 → 章节路径、页码、定位状态 | 表格隔断正文后仍能继承所属章节 |
| `chunk_document.sql` | 解析结果和配置 → 持久化块 | 协调两条切分路径、原生计数及硬上限验收 |
| `compatibility.sql` | 旧算法入口 → 新入口 | 保留既有配置及实验标识，不复制算法 |

算法入口叫 `CHUNK_STRUCTURED_MARKDOWN`。旧配置名 `markdown_header_table_1200_200` 和 `chunk_method=markdown_header_table` 已被块、搜索服务与实验引用，因此保留；旧入口只转调新入口。以后新配置可以用 `chunk_method=structured_markdown`。事务和同配置结果替换由外层 `CHUNK_DOC` 负责，helper 不调用数据库。

## 正文、表格与章节如何衔接

正文使用 `SPLIT_TEXT_MARKDOWN_HEADER`，按 `#`、`##`、`###` 识别章节，同时按配置的 1200 字符、200 overlap 细切。全文先去空行和行尾空白，是为了减少函数改写空白造成的定位失败；代价是空行所表达的段落间隔消失，原始解析结果仍保留。

表格使用管道表头与 `| --- |` 分隔行识别。紧邻表格的前置表名及缩写说明与表头一起作为 prefix，数据按行组装。只有第一格有字的行被视为组标签，首列空白的开头行被视为多层表头。这是确定性的规则，不是理解表格语义的模型。

例如论文中有：

```markdown
# Results
## Cardiovascular outcomes
Table 2. Mortality by treatment
| Treatment | Deaths (%) |
| --- | --- |
| Group A | |
| Low dose | 12 (8.0) |
| High dose | 7 (4.7) |
```

若两行数据需要分块，两个块都带 `Table 2`、`Treatment / Deaths (%)` 和 `Group A`，而不是只留下 `7 (4.7)`。两个块的 `section_path` 都是 `Results > Cardiovascular outcomes`。即使表名写成 `### Table 2...`，也不把它当成正文新章节；表格后的正文继续继承真正的章节。

章节路径从全文标题位置计算，而不是从被表格分开的每个 TEXT 段重新起算；新的 h2 清除旧 h3。路径保存在元数据中，不自动拼进正文 embedding。检索时如何使用章节，见 [serving](../../../../serving/README.md)。表名和表头属于表格块内的上下文；附近正文、表下注释不会自动加入表格块。

## 长度与引用的取舍

表格软目标是 450 token，为重复上下文留余量。逐行计数相加只估算预算；完整候选再用同一个 `COUNT_TOKENS` 精确计数，最终硬上限由配置提供（目前 512）。表头或单行过长时才递归补切，避免文件入库失败；代价是这些少数块不再保证完整重复表头。正常正文不用重复进行第二轮细切。

正文候选通过原文子串定位，下一块从上一块起点之后查找，以允许 overlap。无法定位时引用整个 TEXT 段的页码范围。表格引用根据包含的数据行及重复组标签的位置计算；补切后代保留原候选的页码范围。页码从 0 开始，范围可能较宽，不能把合成的重复表头块说成原文的一段连续子串。

## 当前边界

- 相邻的新表头可以划分两张表，但重复表头的跨页续表也可能被识别为两段；目前不猜测它们是否同一张表，后半段可能缺表名或组标签。
- 首列空白不一定是多层表头，只有第一格有字也不一定是组标签；误识别可能重复一行数据，不能保证复杂合并单元格的含义。
- 仅识别有外侧管道、标准分隔行的 Markdown 表格；HTML、图像表格、分离表名和多行表名不保证识别。表下注释及脚注可能留在正文。
- 一个答案需要多组数据时，512 窗口仍可能把证据分散；保住表格上下文不等于一定能在单块中回答问题。

因此这个策略用于固定语料上的实验，不能声称已完整解决所有医学表格。表格章节归属与转义管道修复已通过本地回归；三篇真实论文在 Snowflake 临时表重切后，正文、章节、页码和 token 与原结果一致。正式块尚未全库回填，已有实验指标仍使用原块，见 [实验记录](../../../../../docs/experiments/README.md)。
