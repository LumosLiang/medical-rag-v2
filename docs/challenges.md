# 工程难点与解决路径

医学论文 RAG 的难点不只是找到相关文档，而是保留能够回答问题的完整证据，再让用户核对生成的结论。项目从逐页 recursive 切分起步，通过固定题集上的离线对照实验，逐步调整文件处理、论文切分、检索和引用展示。

## 文件变化如何进入处理链路

原始 PDF 存在 Azure，解析和检索运行在 Snowflake。文件可能在路径不变的情况下被覆盖，处理链路既要发现变化，也要区分旧版本和新版本。

Azure Storage 将新增、覆盖和删除事件通过 Event Grid 发到 Storage Queue；Snowflake notification integration 消费通知并刷新 directory table，Stream 捕获目录变化，Task 调度后续处理。业务过程只消费 Stream，不自行轮询文件列表或读取队列。这样，变化发现与耗时的解析、切分分开，各自承担明确的职责。

文件版本以 `(relative_path, etag)` 标识，用于复用解析结果和精确删除旧块。ETag 是存储端提供的版本标识，不需要业务代码重新读取整个 PDF 计算哈希。这不是因为 MD5 无法发现同名文件的内容变化：真正按文件内容重新计算的 MD5 可以用于内容校验，文件名是否改变与此无关；ETag 也不等同于内容哈希。

Stream 保存消费区间内的净变化，不是每一次存储事件的日志，因此先把变化持久化到 FILE_CHANGES，再分类处理。新增、覆盖和删除链路均已验证。当前覆盖处理先删除旧版本，新版本失败时会暂时不可检索，失败自动重试尚未实现。

## 原始 PDF 留在湖上，解析结果进入 Snowflake

AI_PARSE_DOCUMENT 可以直接读取 external stage 指向的 Azure PDF，不必先把文件复制到 Snowflake 内部 stage。项目因此保留一份湖上的原始文件，省去额外的复制步骤和副本管理；Snowflake 保存解析结果、文档块和搜索索引。这里减少的是原始文件的重复落地，并不是消除了读取时的数据传输。

论文包含标题、表格和跨页正文，所以选择 LAYOUT，而不是只提取文字的 OCR。LAYOUT 返回 Markdown，page_split 保留物理页号，后续可以利用标题结构切分并追溯页码。解析结果按文件版本缓存，调整切分时不必重复解析。

取舍是后续处理依赖解析质量。Markdown 中缺失的表头、错误的数字或符号，不能通过扩大切分窗口补回来；原始 PDF 仍是审核依据。

## 从按页切分到保留章节与完整证据

### 先拼接全文，解除页边界的影响

基线对每页做一次 recursive 切分，1200 字符、200 字符 overlap，不额外处理论文结构。一个 Results 章节跨到下一页时，页边界会强制切断正文；下一页若没有重复标题，也无法仅从该页恢复所属章节。

改进流程先规范化各页，再按页序拼接全文，记录每页的字符范围。正文使用 Snowflake 原生 Markdown 标题切分，完整章节路径从全文标题位置恢复，块的页码由字符位置换算。这样，跨页正文可以继承上一页的章节；是否继续细切由章节和块大小决定，而不是由 PDF 页边界决定。

规范化去掉空行和行尾空白，减少标题切分函数改写空白后无法定位原文的问题。代价是丢失段落空白；原解析结果仍保留。少数定位失败的块使用所属文本段的页码范围，不伪装成精确定位。

### 清理不服务于当前问答目标的内容

参考文献列表和出版许可信息占据篇幅，也可能因重复出现论文标题、作者和主题词而干扰正文检索。长窗口配置按明确的 References 等标题过滤参考文献，并清理明确的版权、许可行，不按正文中的引用数字删文字。

参考文献本身有信息价值，只是不属于当前正文证据问答的重点。保守规则减少误删正文的风险，但无法覆盖所有缺少标准标题的参考文献；若以后支持文献关系查询，需要重新考虑这项选择。

### 表格需要完整性，不能只按字符长度切

论文中的数值依赖表名、列标题、行标签，有些问题还需要同时比较多个组。普通切分可能让表头和数据分离；即使每个碎块都有表头，也可能没有任何一个块包含回答所需的全部数据。

项目把表格从正文中提取出来，优先整表保留；预算不足时优先按组，再按行拆分，每块重复表名、表头和组标签，并保留完整章节路径及可识别的紧邻脚注。旧模型窗口为 512 token，有的表头本身就超过窗口，单靠调整切分规则无法同时满足完整性和输入上限。

因此引入 Arctic 8K embedding 模型，为更完整的证据提供空间。8K 是容量上限，不是每个块的目标大小：正文以 1024 token 为目标上限，摘要和表格优先完整保留，表格软预算为 8000，模型硬上限为 8192。较大块能保留更多关系，但也可能混入不同主题、降低检索针对性，并扩大用户核对引用的范围，因此不同内容采用不同预算。

超长表格仍按组、按行拆分；极端情况下，例如重复表头本身已超限，递归补切兜底不能保证完整表头。本次 209 篇语料中，识别出的 171 段摘要和 618 张表格全部单块保留，最长块为 2918 token，没有表格触发 8000 token 软预算。这验证了已识别内容的保留效果，不代表所有 PDF 表格都被正确解析，也不代表跨页续表已经全部合并。

## 找到论文之后，还要找到正确证据

文档级命中率很高，并不意味着论文内的正确块排在前面。项目分别检查两个问题：是否存在包含完整证据的块，以及这个块是否进入前 k 个结果。前者指向解析和切分，后者指向检索表达与排序。

最初结构化切分提高了证据完整性，但仅以正文搜索时，Hit@5 反而从 0.68 降到 0.62。章节标题被保存在元数据中，没有参与正文搜索，结构改善并未自动变成检索收益。后续使用 multi-index，让正文参与向量和关键词检索、完整章节路径参与独立关键词检索，再调整关键词、向量和原生 reranker 权重，旧 512 模型方案的 Hit@5 达到 0.82。

长窗口实验保留这套请求配置，比较旧方案、旧块只换模型、新模型配新切分三组。只换模型的 Hit@5 仍为 0.82；配合新切分后达到 0.84，Hit@10 从 0.86 提高到 0.94。收益来自组合方案，不能全部归因于模型窗口。

从最初基线到最新实验，结果如下：

| 指标 | 逐页 recursive 基线 | 8K 模型与结构化切分 |
|---|---:|---:|
| 证据 Hit@5 | 0.68 | 0.84 |
| 证据 Hit@10 | 0.74 | 0.94 |
| MRR@10 | 0.439 | 0.686 |
| 单块证据可覆盖率 | 0.86 | 0.98 |

新实验各组运行两轮，指标一致。相较旧 512 最佳方案，新方案有 16 题排名改善、5 题下降，说明更多上下文并不保证每题更好。历史上也观察到重复请求的 reranker 分数波动，因此保留重复运行结果，而不是挑选一次最高分。完整配置和逐题分析见 [8K 实验报告](experiments/arctic-8k.md)。

## 评测依据独立于切分

如果题目绑定某一种策略的 chunk_id，切分一变，正确答案的定义也会随之变化。项目用原始 PDF、文件哈希、页码、参考答案和证据原文建立 50 道人工审核题；模型辅助起草，最终对照 PDF 审核。同一套题可以复用于不同切分和搜索配置。

这属于固定语料上的离线对照实验，不是将线上用户随机分流的 A/B 测试。Hit@k 衡量前 k 块中是否有一个块覆盖完整证据，MRR 衡量首个覆盖块的排名；这里不把 Hit@k 写成标准 Recall@k。

这套设计把“切分后根本没有完整证据”和“有证据但排名靠后”分开，让改进有依据。当前评分仍是词袋启发式，不能判断数字与组别的对应关系；50 题已反复用于调参，结果尚需独立题集验证，也不代表生成答案质量。评测步骤与规则见 [评测说明](../eval/README.md)。

## 带引用的回答与校验边界

只要求模型在回答后加上 [1]，不能保证每条结论都有出处，也不能保证来源和引文真实存在。项目使用结构化输出，把回答定义为结论列表；每条结论包含引用列表，每条引用包含来源编号 source_id 和原文摘录 quote。

后端收到输出后，逐条检查结论是否有引用、编号是否属于本次检索，以及摘录是否存在于对应片段。匹配只容忍空白差异，不改数字或标点。校验失败就返回错误，不展示或保存这份答案；通过后，由后端生成引用标记，文档和页码直接取自检索结果，不让模型编造。

前端把结论、引用原句和来源关联展示，用户可以查看对应文档、页码范围和完整片段。这样既能拦截无效来源和编造摘录，也给用户提供核对答案的依据。引用合法不等于结论正确：原文存在仍不能证明它支持模型的解释，医学结论是否保留人群、条件和不确定性，需要语义核验。目前没有独立的自动语义核验。

逐结论引用版本已部署到 SPCS，服务身份下的检索、生成与引用校验调用通过。少量固定问题验收不能替代正式生成质量评测；无答案问题仍出现受控生成失败，不能宣称已可靠拒答。

## 会话记录与模型上下文分开管理

前端在 Streamlit session_state 中保留最近 20 轮问答及各轮来源，超出后删除最早记录，避免展示历史无限增长。当前实现解决的是会话内展示和引用归属；历史尚未送给后端或模型，因此不是已经实现了多轮理解。

后续可先用最近几轮理解指代，将追问改写成独立问题后重新检索。历史用于理解问题，本次检索证据用于支持回答。若需要跨会话保存，再引入数据库存储历史和摘要；保存在哪里与给模型选择哪些内容，是两个独立职责。摘要压缩、按需取回和持久化均尚未实现，不作为本轮已完成的成果。
