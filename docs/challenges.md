# 工程难点与解决路径

项目的主要问题集中在文件变化如何可靠进入检索、论文结构如何保留，以及检索和回答如何得到可核对的评价。以下记录已采用的方案、实际结果与尚未解决的边界。

## 文件事件与处理任务解耦

PDF 位于 Azure，处理与搜索位于 Snowflake。直接轮询文件列表会让业务代码同时承担变化发现和文档处理；直接在上传请求中解析则会把耗时计算与上传绑定。

项目采用发布订阅链路：Storage 的新增、覆盖和删除事件经 Event Grid 进入 Storage Queue，Snowflake notification integration 消费通知并刷新 directory table。Stream 记录目录元数据的净变化，Task 在有变化时触发入库过程。业务过程消费 Stream，而不是自行读取队列；storage integration 单独负责文件读取权限。

Stream 是消费区间内的净变化，不是完整事件日志。因此先通过 `INSERT SELECT` 将变化持久化到 FILE_CHANGES，再按文件路径和 etag 分类处理。切分结果按文件版本和配置隔离，同版本、同配置的删除与写入由一个事务完成。

新增、覆盖和删除的自动链路已通过实测，文件不需要复制到 Snowflake 内部 stage。当前尚无失败自动重试；覆盖时先删除旧版本，若新版本处理失败，文档会暂时不可检索。Task 成功结束也不等于所有文件成功，仍需核对 FILE_CHANGES。

## 跨页正文与表格的切分

医学论文的章节常跨页，表格的数值依赖表名、列标题和行标签。逐页通用字符切分容易丢失章节归属，也可能把数值与解释它的上下文分开。

基线保留一次 recursive 切分与 overlap，便于建立可复现的对照。改进策略把规范化后的页面拼成全文，保留页边界坐标；正文使用 Snowflake 原生 Markdown 标题切分，表格独立提取并按行组组装，拆分时重复表名、表头及组标签。章节路径和页码作为元数据写回，超出窗口的候选递归补切。

固定语料上，单块证据覆盖上限由 0.86 提高到 0.94，表格题由 2/8 提高到 5/8。但结构更完整没有直接带来前五名命中率提升：仅以正文检索的 Hit@5 从基线 0.68 降到 0.62。完整表头有时已超过 512 token，少量兜底补切必须牺牲上下文完整性；跨页续表、复杂表头和脚注关联仍有限制。这是下一阶段继续研究的核心，而非已经完成的优化。

## 文档定位与证据排序

检索能把正确论文排在首位，并不保证论文内的正确片段也排在首位。章节切分将标题保存在元数据后，单独检索正文会削弱章节信号；单块覆盖不足与排序不足也需要分别诊断。

项目对比正文、标题前缀和完整章节路径的独立关键词索引，并在 multi-index 上调整关键词、向量和原生重排权重。当前应用采用正文向量索引与正文、章节路径两个关键词索引。

历史最佳证据 Hit@5 为 0.82、MRR 为 0.593；复验为 0.78、0.569，文档级 Hit@1 仍为 1.00。同源块的关键词和向量分数一致，排名变化集中在重排分数；小规模关闭重排对照稳定。现象已定位到重排环节，但没有证据证明服务内部超时或降级。实验保留重复运行结果，不以挑选一次较高成绩代替稳定提升。

下一阶段目标是证据 Hit@5 与 MRR 均达到 0.90。候选因素包括切分与上下文组织、检索候选数量、重排及查询改写；尚未选定下一项实现。

## 评测依据独立于切分

如果正确答案绑定某一种策略的 chunk_id，调整切分后便无法公平比较；单看是否找到论文，又无法衡量证据是否完整。

题集以原始 PDF、文件哈希、物理页码、参考答案和证据原文建立。PDF 文字层用于起草和定位，人工对照 PDF 审核后冻结问题 ID。检索实验记录原始 top-k，评分和检索分开，便于复核历史结果。覆盖上限区分“当前块没有完整证据”和“存在证据但没有排进前 k”。

当前 50 题可复用于不同切分与索引方案，不依赖 chunk_id。指标是单块证据 Hit@k 与首个命中排名的 MRR，尚未衡量多块联合回答能力。词袋评分不能验证数值与组别的对应关系；两题证据表名待建立修订版本。同一题集已用于调参，最好成绩属于探索结果，后续需要独立题集验证。

## 带引用的回答与校验边界

生成模型可能输出没有证据支持的医学结论，也可能引用不存在的来源。仅在提示词中要求引用，无法保证输出格式和编号合法。

后端为本次检索片段分配来源编号，将原文与编号一起送入模型，要求仅依据证据回答，证据不足时拒答。返回后校验引用编号是否属于本次来源，并拒绝无引用的正常回答。前端展示对应文档、页码和证据原文，用户可以核对。

该链路已通过云端 HTTP 验收。编号合法不等于结论有证据支持，当前没有自动验证每条结论。后续改进是结构化引用：模型逐条返回结论及 `source_ids`，后端校验后由前端渲染 `[1]` 等标记，再逐步验证结论与证据的支持关系。这项改进尚未实现。
