# 切分对照：保住证据与排准证据是两件事

章节表格策略尝试解决跨页段落和表格上下文被拆散的问题。它提高了单块覆盖上限，但正文检索缺少标题信号时，前五名命中反而下降。因此不能仅凭块结构更完整就认定检索效果更好。

## 为什么保留表格专门处理

全库提取到 623 个表格（含 1 个仅表头），25 处相邻 TABLE 边界。1635 个表格候选中有 16 个超过 512 token，集中在 5 篇，最大 710；其中一张表头本身 519 token。因此“完整重复表头”与“所有块不超过 512”无法始终兼得，少量超长候选采用 recursive 兜底，不保证保留完整表头。

8 道表格题中，正文与表格候选联合覆盖由 2/8 提高到 5/8；只有 TABLE 候选不能覆盖那两道实际证据在正文的题。

| 文档 | 基线覆盖 | 章节表格候选联合覆盖 |
|---|---|---|
| PMC10047748 | 是 | 是 |
| PMC10879646 | 否 | 是 |
| PMC12412449 | 否 | 是 |
| PMC12596571 | 否 | 是 |
| PMC12681061 | 否 | 否 |
| PMC13384364 | 是 | 是 |
| PMC8721628 | 否 | 否 |
| PMC9238046 | 否 | 否 |

PMC8721628 的证据要求 years，但解析表头没有该词；另两题要求多个行组一起出现在单块，窗口分组使其分散。用户接受记录这些限制后继续，不修改题目或评分凑到覆盖目标。最终表格题可覆盖 5/8、top-10 命中 3/8，说明仍有排序损失。

## 实现验收与结果边界

章节表格最终最大 511 token，空块、NULL token、超限、重复 ID、文件版本及页码错误为 0；1841 块跨页。正文候选 12850 个中 48 个定位回退（0.374%），回退引用所属 TEXT 段范围。单篇重复切分的 ID、文本、页码和 token 一致，超限异常可由外层事务恢复旧块。基线允许超窗，411 块超过 512，符合其设计。

这些检查验证了旧实现的结构与执行，没有证明复杂表格的语义完全正确。两题证据表名问题、跨页续表和启发式表头识别的限制见 [策略说明](../../src/ingestion/sql/chunk/structured_markdown/README.md) 与 [评测说明](../../eval/README.md)。后续用章节信号改进检索，见 [检索对照](search.md)。
