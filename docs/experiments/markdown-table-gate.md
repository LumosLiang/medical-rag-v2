# Markdown 表格切分：第一道门槛

2026-10-04，Snow CLI 实测。第一道门槛的实测记录。用户随后已确认继续实施；完整过程、209 篇回填、独立搜索服务及两份 50 题实验均已验收，最终结果如下。

## 已实现

`src/sql/ingest/chunk/markdown_header_table/` 下按职责拆分的辅助函数：

- `NORMALIZE_MARKDOWN_PAGES`：删除空行和行尾空白，全文拼接；返回规范化文字与每页的字符范围。偏移为 0 起始、右端不包含。
- `SPLIT_TABLE_SPANS`：识别表名、Markdown 表头、多层表头及数据行；返回 TEXT/TABLE 的精确原文范围。新表头和分隔行可分开没有空行间隔的表格。只跨过缩写说明行关联前置表名，不跨越普通正文猜测。
- `PACK_TABLE_ROWS`：使用 Snowflake 预先计算的 token 数，优先保留完整行组；拆组时重复组标签，所有块重复表名和表头。返回候选块，最终整体 token 数仍由 SQL 复核。

SQL 使用原生 COUNT_TOKENS。相关 FLATTEN/ARRAY_AGG 留在调用查询中，不封装进 SQL UDTF；实测相关 SQL UDTF 调用会报 Unsupported subquery type。没有另引 tokenizer 或编排框架。

- `LOCATE_MARKDOWN_CHUNKS`：在规范化全文上定位候选块，按标题级别维护章节路径；正文切分仍交给原生函数。定位失败时取所属 TEXT 段页码范围。
- `CHUNK_MARKDOWN_HEADER_TABLE`：十参数算法入口，调用上述 helper、原生 splitter 和 COUNT_TOKENS；仅超限块递归补切，写入后严格检查，异常交给 CHUNK_DOC 回滚。

## 实测

固定语料快照 `corpus_2026_10_03`：209 篇。全库识别 623 个表格（含 1 个只有表头的段），其中 25 处相邻 TABLE 边界；每个 span 都能按偏移原样取回源文本。PMC8721628 的三个表格分别关联 Table 1、2、3，没有把“Table 2 illustrates ...”正文误当表名。

生成 1635 个表格候选块，涉及 182 篇；16 块超过 512 token，集中在 5 篇，最长 1021 token。进一步逐行复核发现：这些表格的完整表头加单行本身就超过 512；PMC9697043 的表头本身有 519 token。只按数据行分组无法解决。

## 用户已确认

1. 少数超长表格允许 recursive 补切兜底，此时不保证重复完整表头；后代保留母块的章节和页码范围，不宣称更窄的精确页码。
2. 保留原题集、评分与 5/8 的结果，记录已核对的限制后继续，不改题凑到 6/8。

配置 `markdown_header_table_1200_200` 保持 inactive；全文切分使用原生 header splitter 的 1200/200，未再做第二轮正常正文切分。
